计算能力（Compute Capability）：GPU 的基因编码

CC X.Y → SM version sm_XY

📌 核心概念板书

  • 每个 NVIDIA GPU 都有一个计算能力版本号，格式为 X.Y（主版本.次版本）
  • 计算能力指示了 GPU 支持的特性并规定了硬件参数
  • 计算能力直接对应流式多处理器（SM）的版本号，例如 CC 12.0 对应 sm_120

🎙️ 讲师详细口播讲稿

计算能力，英文叫 Compute Capability，简称 CC，就像是每一款 GPU 的基因编码。它用主版本号和次版本号来表示，比如 12.0，主版本是 12，次版本是 0。这个数字可不是随便定的，它直接告诉你这块 GPU 支持哪些特性，甚至规定了硬件的一些关键参数，比如有多少个流式多处理器、每个处理器有多少寄存器等等。更妙的是，计算能力直接对应 SM 的版本号。比如一块 CC 12.0 的 GPU，它的 SM 版本就是 sm_120。这个版本号在编译时用来标记二进制文件，确保你的代码能在正确的硬件上运行。所以，下次你看到 sm_80、sm_90 这样的标签，就知道它们对应着不同计算能力的 GPU。记住，CC 是 GPU 的身份证，也是你优化代码时的重要参考。

深入微架构：计算能力与 SM 版本的关系

nvcc -arch=sm_120

📌 核心概念板书

  • 计算能力主版本号决定 SM 的大架构，次版本号表示小幅改进
  • SM 版本号用于编译时指定目标架构，如 -arch=sm_120
  • 不同计算能力的 GPU 在硬件参数和特性支持上存在差异

🎙️ 讲师详细口播讲稿

现在，让我们用一段动态几何模拟来直观理解计算能力与 SM 版本的关系。想象一个 GPU 内部，有多个流式多处理器（SM）像小工厂一样并行工作。计算能力的主版本号，比如 12，决定了这些工厂的基本设计蓝图——它们有多少个 CUDA 核心、多少共享内存。次版本号，比如 0，表示在这个蓝图上的小修小补。当我们编译代码时，指定 -arch=sm_120，就是告诉编译器：请生成能在这些特定工厂里运行的机器码。如果版本不匹配，就像给旧工厂送去了新图纸，机器无法运转。所以，理解 CC 和 SM 版本，是确保你的程序能在目标 GPU 上高效执行的第一步。下面的动画将展示不同 CC 版本下 SM 的布局变化，帮助你建立直观印象。

NVIDIA 驱动：GPU 的操作系统

NVIDIA Driver r580

📌 核心概念板书

  • NVIDIA 驱动是 GPU 的操作系统，必须安装在主机操作系统上
  • 驱动是所有 GPU 使用的基础，包括显示和图形功能
  • 驱动版本号如 r580，独立于 CUDA Toolkit 版本

🎙️ 讲师详细口播讲稿

如果把 GPU 比作一台强大的计算机，那么 NVIDIA 驱动就是它的操作系统。没有驱动，GPU 就是一块昂贵的砖头。驱动必须安装在你的主机操作系统上，无论是 Windows、Linux 还是其他系统。它不仅是 CUDA 的基础，还负责所有其他 GPU 用途，比如玩游戏时的 Vulkan 或 Direct3D 渲染。驱动有自己的版本号，比如 r580，这个版本号与 CUDA Toolkit 的版本是独立的。你可以把驱动看作底层管家，它管理着 GPU 的硬件资源，为上层软件提供统一接口。所以，在搭建 CUDA 环境时，第一步永远是安装合适版本的 NVIDIA 驱动。记住，驱动是地基，CUDA Toolkit 是建在地基上的高楼。

CUDA Toolkit：开发者的瑞士军刀

CUDA Toolkit: nvcc, libraries, tools

📌 核心概念板书

  • CUDA Toolkit 是一套库、头文件和工具，用于编写、构建和分析 GPU 计算软件
  • 它是独立于 NVIDIA 驱动的软件产品
  • CUDA 运行时是 Toolkit 提供的一个特殊库，包含 API 和语言扩展

🎙️ 讲师详细口播讲稿

接下来是 CUDA Toolkit，它是开发者的瑞士军刀。想象你要造一辆赛车，Toolkit 提供了所有工具：编译器 nvcc、性能分析器、数学库、调试工具等等。它是一套完整的软件开发包，让你能编写、构建和优化 GPU 程序。注意，Toolkit 是独立于驱动的软件产品，你可以安装多个版本的 Toolkit，但驱动通常只有一个。Toolkit 里有一个非常核心的组件——CUDA 运行时。它既提供 API 函数，比如分配内存、拷贝数据、启动内核，也提供语言扩展，比如在 C++ 中用 __global__ 声明内核。运行时 API 是我们最常用的接口，它建立在更底层的驱动 API 之上。所以，Toolkit 是你日常开发的工具箱，而运行时是你最常拿的那把螺丝刀。

运行时 API vs 驱动 API：双剑合璧

cudaMalloc() vs cuMemAlloc()

📌 核心概念板书

  • CUDA 运行时 API 构建在驱动 API 之上，提供更简洁的接口
  • 驱动 API 是 NVIDIA 驱动暴露的底层 API，功能更全面但更复杂
  • 两者可以互操作，有些高级特性仅驱动 API 支持

🎙️ 讲师详细口播讲稿

很多初学者会混淆运行时 API 和驱动 API。简单说，运行时 API 是高层封装，让你用起来更顺手，比如 cudaMalloc、cudaMemcpy 这些函数。而驱动 API 是更底层的接口，由 NVIDIA 驱动直接提供，功能更强大但也更繁琐。运行时 API 实际上是在驱动 API 之上实现的，所以所有运行时能做的事，驱动 API 都能做，只是代码量更大。反过来，有些高级特性，比如更精细的内存管理或上下文控制，只有驱动 API 才提供。好消息是，你可以在同一个程序里混用两者，它们可以互操作。对于大多数应用，运行时 API 足够了；但当你需要极致控制时，驱动 API 就是你的秘密武器。理解这两者的关系，能帮你更好地设计软件架构。

版本兼容性：GPU、驱动与 Toolkit 的三角关系

Driver ≥ Toolkit ≥ GPU CC

📌 核心概念板书

  • CUDA 兼容性文档详细说明了 GPU、驱动和 Toolkit 版本之间的兼容规则
  • 驱动版本决定了支持的 CUDA 版本上限
  • Toolkit 版本需要与驱动版本匹配，同时考虑 GPU 的计算能力

🎙️ 讲师详细口播讲稿

在实际开发中，版本兼容性是个绕不开的话题。想象你有一块最新的 GPU，安装了最新的 Toolkit，但驱动却是旧的，结果程序跑不起来。这是因为驱动版本决定了它能支持的最高 CUDA 版本。NVIDIA 提供了详细的兼容性文档，帮你理清这三者之间的关系。一般来说，驱动是向下兼容的，新驱动可以运行旧版 CUDA 程序，但旧驱动无法运行新版 CUDA 程序。此外，你的 GPU 计算能力也限制了你能使用的 CUDA 特性。所以，在搭建环境时，一定要查兼容性表：先看 GPU 的计算能力，再选合适的 Toolkit 版本，最后确保驱动版本足够新。记住这个三角关系，能帮你避免很多坑。

总结与最佳实践

Checklist: CC → Driver → Toolkit → Code

📌 核心概念板书

  • 理解计算能力（CC）和 SM 版本，确保编译目标正确
  • 安装合适的 NVIDIA 驱动，它是 GPU 的基石
  • 使用 CUDA Toolkit 和运行时 API 高效开发，必要时深入驱动 API
  • 始终检查版本兼容性，避免环境问题

好了，我们来总结一下。CUDA 平台是一个由硬件和软件组成的生态系统。计算能力（CC）是 GPU 的基因，决定了它能做什么；SM 版本号是编译时的目标标签。NVIDIA 驱动是 GPU 的操作系统，必须安装且版本要足够新。CUDA Toolkit 是你的开发工具箱，运行时 API 是你最常用的工具，而驱动 API 是底层利器。最后，永远不要忽视版本兼容性——查文档、对版本，能节省你无数调试时间。最佳实践是：明确你的 GPU 计算能力，选择匹配的 Toolkit，安装最新驱动，然后开始编写高效的异构程序。希望这几页幻灯片能帮你建立起 CUDA 平台的清晰心智模型，为后续深入学习打下坚实基础。
