CUDA Runtime API vs Driver API

📌 核心概念板书

  • CUDA C++ 是建立在 C++ 之上的并行计算扩展，核心是区分主机（CPU）与设备（GPU）代码。
  • CUDA Runtime API 是最常用的编程接口，它构建在更底层的 Driver API 之上。
  • 学习 CUDA 需要建立“异构计算”心智模型：CPU 负责控制流，GPU 负责数据并行。

🎙️ 讲师详细口播讲稿

各位同学，欢迎来到 CUDA C++ 的世界。在开始写第一行 GPU 代码之前，我们必须先建立一个关键的心智模型：你的计算机里有两个不同的处理器——CPU 和 GPU。CPU 擅长复杂的逻辑控制和串行任务，而 GPU 拥有成千上万个简单核心，专为大规模数据并行而生。CUDA C++ 就是一座桥梁，让我们能用熟悉的 C++ 语法，把一部分计算任务卸载到 GPU 上执行。官方文档强调，本指南聚焦于 CUDA Runtime API，这是最常用的方式，它封装了底层的 Driver API，让开发者不必直接和硬件驱动打交道。所以，请记住：从今天起，你写的每一行代码，都要明确它是在主机上跑，还是在设备上跑。

NVCC 编译器：GPU 代码的诞生之旅

nvcc -arch=sm_80 my_kernel.cu

📌 核心概念板书

  • nvcc 是 NVIDIA CUDA 编译器驱动，负责将 C++ 和 PTX 代码编译为 GPU 可执行文件。
  • 它简化了编译流程，提供熟悉的命令行选项，背后调用多个工具完成不同编译阶段。
  • nvcc 可在 Linux、Windows 及 WSL 上使用，是连接源代码与 GPU 硬件的关键工具。

🎙️ 讲师详细口播讲稿

好，有了异构计算的概念，接下来我们看看代码是如何变成 GPU 能执行的程序的。这就要请出 nvcc——NVIDIA CUDA 编译器驱动。你可以把它想象成一个总指挥，它本身并不直接编译每一行代码，而是调用一系列工具，把 C++ 源代码、PTX 中间代码等一步步转换成 GPU 可执行的二进制。nvcc 提供了非常友好的命令行选项，让你在 Linux、Windows 甚至 WSL 上都能轻松编译 CUDA 程序。官方文档特别指出，nvcc 简化了编译 C++ 或 PTX 代码的过程，你只需要关注自己的源代码，剩下的交给它。所以，每当你执行 nvcc 命令时，背后其实是一场精心编排的编译交响乐。

内核（Kernel）：在 GPU 上并行执行的函数

__global__ void vecAdd(float* A, float* B, float* C) { ... }

📌 核心概念板书

  • 内核是 GPU 上执行的函数，由主机代码调用，但运行在设备上。
  • 使用 __global__ 声明说明符定义内核，它告诉编译器该函数为 GPU 编译并可从主机启动。
  • 内核必须返回 void，并且通常由大量并行线程同时执行。

🎙️ 讲师详细口播讲稿

现在，我们正式进入 CUDA 的核心——内核。什么是内核？简单说，它就是在 GPU 上执行的函数。你可以在 CPU 代码里调用它，但它的实际运行发生在 GPU 上。怎么定义内核呢？用 __global__ 这个声明说明符。它就像给编译器的一个信号：这个函数要编译成 GPU 代码，并且可以从主机端启动。注意，内核函数必须返回 void，因为它不是用来返回值的，而是通过参数（比如指针）来读写数据。官方文档强调，内核被设计成由许多并行线程同时执行。你可以把内核想象成一个工厂里的流水线工人，每个工人（线程）处理一小块数据，成千上万的工人同时开工，这就是 GPU 的威力所在。

内核启动：执行配置与三重尖括号

vecAdd <<<1, 256>>>(A, B, C);

📌 核心概念板书

  • 内核启动通过执行配置指定并行线程数量，不同启动可使用不同配置。
  • 三重尖括号 <<< >>> 是最常用的启动语法，尖括号内为执行配置参数。
  • 执行配置前两个参数是网格维度（grid dimensions）和线程块维度（block dimensions）。

🎙️ 讲师详细口播讲稿

定义好内核后，下一步就是启动它。启动内核时，我们必须告诉 GPU：要用多少个线程来并行执行？这个信息叫做执行配置。CUDA 提供两种启动方式：三重尖括号和 cudaLaunchKernelEx。最常用的是三重尖括号，写作 <<< >>>。尖括号里用逗号分隔的参数就是执行配置，类似函数调用的参数列表。官方示例中，vecAdd <<<1, 256>>>(A, B, C); 表示启动 1 个线程块，每个线程块 256 个线程。这里第一个参数是网格维度，第二个是线程块维度。初学者常误以为尖括号里是函数参数，其实不是——函数参数在尖括号后面的圆括号里。尖括号里是告诉 GPU 如何组织线程的。理解这一点，你就掌握了内核启动的关键。

硬件微架构演示：线程块与网格的并行执行

grid -> blocks -> threads

📌 核心概念板书

  • 执行配置定义了网格（grid）和线程块（block）的层次结构。
  • 网格由多个线程块组成，每个线程块包含多个线程，它们被映射到 GPU 的流多处理器（SM）上。
  • 线程块内的线程可以通过共享内存和同步进行协作，不同线程块之间独立执行。

🎙️ 讲师详细口播讲稿

让我们通过一个动态几何演示，直观感受 GPU 的并行执行。想象一个网格（grid），它由多个线程块（block）组成，就像一座城市由多个街区组成。每个街区里又有许多线程（thread），就像街区里的居民。当我们启动内核时，GPU 的调度器会把不同的线程块分配到不同的流多处理器（SM）上执行。每个 SM 可以同时运行多个线程块，而线程块内的线程又会被分组为 warp（通常 32 个线程），以锁步方式执行。注意，线程块之间是独立的，它们不能直接通信；但同一线程块内的线程可以通过共享内存快速交换数据，并用 __syncthreads() 同步。这个层次结构是 CUDA 性能优化的基石。现在，请看动画：线程块如何被分发到 SM，线程又如何并行执行。

到这里，我们已经走过了 CUDA C++ 入门的关键步骤。让我们回顾一下：第一，CUDA 是异构计算模型，CPU 和 GPU 各司其职；第二，用 nvcc 编译，它会帮你处理复杂的编译流程；第三，用 __global__ 定义内核，内核必须返回 void；第四，用三重尖括号启动内核，尖括号内是执行配置，前两个参数是网格和线程块维度。最后，记住线程的层次结构：网格包含线程块，线程块包含线程。在实际编程中，要根据问题规模合理设置这些维度，才能让 GPU 跑满。现在，你已经具备了编写第一个 CUDA 程序的基础知识，接下来就是动手实践了。
